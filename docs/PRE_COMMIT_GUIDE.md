# 🪝 Руководство по Pre-commit хукам

## Что такое Pre-commit хуки?

**Pre-commit хуки** — это автоматические скрипты, которые запускаются **перед каждым git commit**. Они проверяют ваш код и либо:
- ✅ Пропускают коммит (если всё ок)
- ❌ Блокируют коммит (если есть ошибки)
- 🔧 Автоматически исправляют проблемы (например, форматирование)

### Зачем это нужно?

1. **Качество кода** - автоматическая проверка перед коммитом
2. **Экономия времени** - не нужно помнить команды линтера/тестов
3. **Единообразие** - все в команде используют одни правила
4. **Меньше ошибок в PR** - проблемы находятся до пуша

## 📋 Что проверяют наши хуки?

### 1. Ruff - линтинг и форматирование
```yaml
- id: ruff
  args: [--fix]  # Автоматически исправляет что может
```
**Что делает:**
- Проверяет код на соответствие PEP 8
- Находит потенциальные баги
- Сортирует импорты
- **Автоматически исправляет** простые проблемы

**Пример:** Если вы забыли отсортировать импорты, хук автоматически их отсортирует.

### 2. Ruff Format - форматирование кода
```yaml
- id: ruff-format
```
**Что делает:**
- Форматирует код (отступы, пробелы, длина строк)
- Делает код единообразным
- **Автоматически исправляет** форматирование

**Пример:** Приводит все к единому стилю кавычек, отступов.

### 3. Pytest - запуск тестов
```yaml
- id: pytest-check
  entry: uv run pytest
```
**Что делает:**
- Запускает **все тесты** перед коммитом
- Блокирует коммит, если тесты не прошли

**Важно:** Если хотя бы один тест упал — коммит не пройдёт! 🛑

### 4. Стандартные проверки
```yaml
- check-yaml      # Проверка синтаксиса YAML
- check-toml      # Проверка синтаксиса TOML
- trailing-whitespace  # Удаление пробелов в конце строк
- end-of-file-fixer    # Перенос строки в конце файла
- check-added-large-files  # Защита от больших файлов (>500KB)
- check-merge-conflict     # Проверка на git конфликты
- no-commit-to-branch      # Защита от коммита в main/master
```

## 🚀 Как это работает?

### Автоматический запуск

Когда вы делаете `git commit`:

```bash
git add .
git commit -m "добавил новую функцию"
```

**Автоматически происходит:**

```
1. [Ruff Check] → проверяет код, исправляет что может
   ✓ Passed

2. [Ruff Format] → форматирует код
   ✓ Passed

3. [Pytest] → запускает все тесты
   ✓ 15 tests passed in 2.3s

4. [Check YAML] → проверяет .yaml файлы
   ✓ Passed

... (остальные проверки)
```

### Если проверка не прошла

```bash
git commit -m "добавил новую функцию"

# Вывод:
Ruff....................................Failed
- hook id: ruff
- exit code: 1

sprint_1/palindrome_check/solution.py:5:1: F401 [*] `sys` imported but unused
  |
5 | import sys
  | ^^^^^^^^^^ F401
```

**Что делать:**
1. Исправьте ошибку
2. Добавьте файлы снова: `git add .`
3. Попробуйте коммит ещё раз

### Если хук автоматически исправил файлы

```bash
git commit -m "новая функция"

# Вывод:
Ruff Format.............................Failed
- hook id: ruff-format
- files were modified by this hook

Файлы отформатированы!
```

**Что делать:**
1. Хук уже исправил файлы
2. Проверьте изменения: `git diff`
3. Добавьте исправленные файлы: `git add .`
4. Коммит снова: `git commit -m "новая функция"`

## 📝 Основные команды

### Первоначальная установка (уже сделано!)
```bash
uv add --dev pre-commit
uv run pre-commit install
```

### Ручной запуск всех хуков
```bash
# Проверить все файлы
uv run pre-commit run --all-files

# Проверить конкретный файл
uv run pre-commit run --files sprint_1/palindrome_check/solution.py

# Проверить конкретный хук
uv run pre-commit run ruff --all-files
uv run pre-commit run pytest-check
```

### Обновление хуков
```bash
# Обновить версии хуков до последних
uv run pre-commit autoupdate
```

### Временное отключение хуков

**Вариант 1:** Пропустить все хуки для одного коммита
```bash
git commit -m "сообщение" --no-verify
# или короткая форма:
git commit -m "сообщение" -n
```

**⚠️ Используйте редко!** Только для WIP коммитов или экстренных случаев.

**Вариант 2:** Отключить хуки полностью
```bash
uv run pre-commit uninstall
```

**Включить обратно:**
```bash
uv run pre-commit install
```

## 🔧 Настройка хуков

### Отключить конкретный хук

Откройте `.pre-commit-config.yaml` и закомментируйте ненужный хук:

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    hooks:
      - id: ruff
      # - id: ruff-format  # <-- Отключили форматтер
```

### Изменить настройки pytest

Например, запускать только быстрые тесты:

```yaml
- id: pytest-check
  name: "Pytest: запуск тестов"
  entry: uv run pytest -m "not slow"  # <-- Добавили фильтр
  language: system
  pass_filenames: false
  always_run: true
```

### Исключить файлы/папки из проверки

В `.pre-commit-config.yaml` уже настроено:

```yaml
exclude: |
  (?x)^(
    \.git/|
    \.pytest_cache/|
    __pycache__/|
    \.venv/|
    \.uv/
  )
```

Добавьте свои паттерны, если нужно.

## 🎯 Рабочий процесс с хуками

### Обычная работа

```bash
# 1. Пишете код
vim sprint_1/new_task/solution.py

# 2. Добавляете в staging
git add sprint_1/new_task/

# 3. Коммитите (хуки запустятся автоматически)
git commit -m "feat: добавил решение new_task"

# Если хуки прошли успешно:
✓ Ruff Check
✓ Ruff Format
✓ Pytest
✓ Check YAML
...
[main abc1234] feat: добавил решение new_task

# 4. Пушите
git push
```

### Если тесты упали

```bash
git commit -m "добавил функцию"

# Вывод:
Pytest: запуск тестов...................Failed
FAILED sprint_1/palindrome_check/test_solution.py::test_palindrome

# Что делать:
1. Исправьте тест или код
2. Запустите тесты вручную для проверки:
   uv run pytest sprint_1/palindrome_check/
3. Добавьте исправления:
   git add .
4. Попробуйте коммит снова:
   git commit -m "добавил функцию"
```

### WIP (Work In Progress) коммиты

Если делаете временный коммит и знаете, что тесты не проходят:

```bash
git commit -m "WIP: работаю над функцией" --no-verify
git push
```

**Но!** Перед финальным PR всё равно пропустите через хуки:

```bash
uv run pre-commit run --all-files
```

## 🔍 Диагностика проблем

### Хуки не запускаются

**Проверьте установку:**
```bash
# Должен существовать файл
ls -la .git/hooks/pre-commit

# Переустановите хуки
uv run pre-commit install
```

### Хуки падают с непонятной ошибкой

**Запустите вручную для детального вывода:**
```bash
uv run pre-commit run --all-files --verbose
```

### Pytest зависает

Если тесты долго выполняются, можно:

1. **Добавить таймаут:**
```yaml
- id: pytest-check
  entry: timeout 60 uv run pytest  # 60 секунд
```

2. **Запускать только быстрые тесты:**
```yaml
- id: pytest-check
  entry: uv run pytest -m "not slow"
```

## 💡 Советы

1. **Коммитьте часто, маленькими порциями** - хуки будут работать быстрее
2. **Запускайте `--all-files` периодически** для проверки всего проекта
3. **Не используйте `--no-verify` без крайней необходимости**
4. **Обновляйте хуки**: `uv run pre-commit autoupdate`
5. **В CI/CD тоже запускайте pre-commit** для дополнительной проверки

## 🎓 Для новичков в команде

После клонирования репозитория:

```bash
# 1. Установите зависимости
uv sync

# 2. Установите pre-commit хуки
uv run pre-commit install

# 3. Проверьте что всё работает
uv run pre-commit run --all-files
```

Готово! Теперь при каждом коммите код будет автоматически проверяться. ✨
```
## 📝 Рекомендуемый рабочий процесс

### Ежедневная работа

```bash
# 1. Работаете над кодом
vim sprint_1/task/solution.py

# 2. Сначала запускаете хуки (проверка + автоисправление)
uv run pre-commit run --all-files

# 3. Смотрите что изменилось
git status
git diff

# 4. Добавляете ВСЁ (ваши изменения + исправления хуков)
git add .

# 5. Коммитите (хуки уже ничего не изменят)
git commit -m "feat: решил задачу X"

# 6. Пушите
git push
```

### Быстрые коммиты (если уверены в коде)

```bash
# 1. Добавляете файлы
git add .

# 2. Коммитите (хуки запустятся автоматически)
git commit -m "ваше сообщение"

# 3. Если хуки что-то исправили - повторяете
git add .
git commit -m "ваше сообщение"
```
