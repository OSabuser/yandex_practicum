# 🚀 Commit & Push с pre-commit хуками

## Команды

| Команда | Описание |
|---|---|
| `just cp "сообщение"` | Коммит + пуш с проверками |
| `just cp-wip "сообщение"` | Коммит + пуш **без хуков** (только WIP!) |
| `just lint` | Только запустить хуки, без коммита |
| `just status` | Статус репо + последние 5 коммитов |

## Как работает `just cp`

```
git add .
    ↓
git commit  →  хуки исправили файлы?  →  git add . → повтор (до 2 раз)
    ↓                                                       ↓
 успех                                               всё равно падает → выход с ошибкой
    ↓
git push --set-upstream origin <ветка>
```

## Хуки в проекте

| Хук | Действие |
|---|---|
| `ruff --fix` | Линтинг, авто-исправление |
| `ruff-format` | Форматирование кода |
| `pytest` | Запуск всех тестов |
| `check-yaml`, `check-toml` | Валидация конфигов |
| `trailing-whitespace`, `end-of-file-fixer` | Чистка пробелов |
| `check-merge-conflict` | Проверка конфликтов |
| `check-added-large-files` | Блокировка файлов > 500KB |

> ⚠️ Хуки с авто-исправлением (ruff, trailing-whitespace и др.) модифицируют файлы
> и прерывают коммит — скрипт автоматически делает `git add .` и повторяет коммит.

## Если что-то пошло не так

```bash
# Хуки падают — смотрим детально
just lint

# Тесты не проходят — запускаем отдельно
uv run pytest

# Нужно срочно закоммитить сломанное
just cp-wip "WIP: в процессе"
```
